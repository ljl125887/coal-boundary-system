# 算法与工程设计

## 算法数据流

LAS 使用内存映射分块读取。点云汇总为计数、最小/最大/平均高程及颜色栅格，随后进行地面估计和相对高度计算。候选区结合高度及可选分类概率，按低洼沟槽分堆，再恢复连续坡面和合并局部坡脚碎片。面积由计算几何获得，体积由对应栅格的相对高度积分得到。

## 计算边界与展示边界

展示轮廓追踪原始点云细网格上的坡脚证据。`toe_first` 策略优先选择允许面积容差内更低的等高线，再平滑局部锯齿。`area_first` 保留为对照策略。高度场校正、搜索走廊和缺口补全共同约束结果。

展示轮廓不用于替换审计计算几何；仅靠视觉圆润不能证明边界更准确。平滑也无法保证每个位置都与实际坡脚完全重合。

## 缓存键与复用

共享命名空间由 `dataset_fingerprint + config_hash` 哈希生成，缩短目录名以兼容 Windows 路径长度。配置哈希排除连接配置和运行输出路径，完整哈希仍写入缓存并复核。展示缓存另外校验计算边界指纹、算法名称与参数。

当前数据指纹使用文件绝对路径、大小、修改时间和点数，并非逐字节内容哈希。若外部程序改变内容却同时保留这些属性，系统不能保证识别；此时需强制重算。缓存命中仍读取文件头，但避免遍历点云主体。

缓存写入使用临时文件和原子替换；共享缓存生成通过文件锁串行化。文件锁带超时与过期恢复，长于过期阈值的计算需调整策略。生产环境应使用持久、可信且 Worker 可写的缓存目录，避免执行中修改输入文件。

## Worker 与服务边界

Worker 从外部后端领取任务，管理租约、进度及结果上报。成果按任务与运行版本隔离，缓存跨运行复用。路径校验限制输入/输出在配置的逻辑根内，单堆复算核对源结果哈希与边界。补传队列用于处理短时连接失败。

仓库只包含 Python 客户端与 Worker；运行完整调度需要实现兼容协议的后端。测试通过本机模拟 HTTP 服务验证交互，不依赖内部网络。

## 技术栈

Python、NumPy、SciPy、Shapely、PyYAML、OpenPyXL、JSON Schema、Tkinter；TensorFlow 为可选模型适配依赖。默认合成演示关闭模型，训练权重不随仓库分发。
